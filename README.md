# Reduction Stepper

A small-step operational semantics visualizer for a subset of SML. Type in a program, hit **Step**, and watch it reduce one redex at a time — the next thing about to happen is highlighted yellow, and the value a substitution just placed is highlighted green for one step.

The interpreter (`stepper-core`) is written in Rust and compiled to WebAssembly; the frontend (`www/`) is a single static HTML page with no build step of its own.

## Quickstart

Requires [Rust](https://rustup.rs/), [`wasm-pack`](https://rustwasm.github.io/wasm-pack/installer/), and Python 3 (for the dev server).

```sh
make serve
```

Then open http://localhost:8585 in a browser. Enter a program, click **Enter formula**, then **Step** to advance one reduction at a time, or **Run to value** to auto-step to completion.

Other targets:

```sh
make build   # compile stepper-core to WASM into www/pkg
make test    # run stepper-core's Rust test suite
make clean   # remove build artifacts
```

Run `make serve PORT=xxxx` to use a port other than 8585.

## The language

The subset supported is real SML syntax:

```sml
val x = 15 * 10
val y = x + 15 * 1000
val z =
    let
        val x = 10
    in
        y < x
    end
```

- `val` declarations, with an optional type annotation (`val x : int = 5`) and a pattern on the left: an identifier, `_` (wildcard), a literal (matches only that exact value), or a tuple pattern `(p1, p2, ...)`, nestable.
- ints and bools, arithmetic (`+ - * div mod ~`, with `div`/`mod` using SML's floor semantics rather than truncating), comparisons (`= <> < <= > >=`, nonassociative — `a < b < c` is a parse error, same as real SML), and short-circuiting `andalso`/`orelse`.
- `if e then e else e`, `let val ... in e end`, tuples `(e1, e2, ...)`.
- `case e of p1 => e1 | p2 => e2 | ...` — pattern matching, tried top to bottom. There's no exhaustiveness checking: a value matching no arm is a runtime failure, same as an unmatched literal `val` pattern (real SML would raise `Match`/`Bind` here; this project doesn't have exceptions yet).

- functions: `fn p : t => e` (the parameter type is mandatory — there's no inference engine), application, `val rec`, and `fun`, which elaborates into the `val`/`val rec` it stands for so you can watch the desugaring.

Not supported (yet): lists, datatypes, exceptions, exhaustiveness checking.

## How stepping works

Each click of **Step** performs exactly one reduction — evaluate one arithmetic subexpression, pick one `if`/`case` branch, unroll one recursive call, or substitute one `val` binding into the rest of the program — and reports what it did (e.g. `Evaluated 1 + 2 to 3`, `Substituted x = 5`). Before you click, the display already shows what the *next* step will act on, highlighted in yellow, so you can predict the reduction before it happens. Anything a substitution just placed is highlighted in green.

## Reading a long program

Click any `fn` to fold it to `fn x => ...`, and click again to unfold it — useful for keeping a recursive function out of the way while you watch it unroll. The width slider sets the column the printer wraps at, so `let`, `case` and long applications break across lines and indent rather than running off the side.

## Project layout

```
stepper-core/          Rust crate: parser, typechecker, stepper, renderer
  src/frontend/         lexer + LALR grammar (lrlex/lrpar) + AST + resolver + typechecker
  src/stepping/         one-reduction-at-a-time evaluator + next-redex finder
  src/pretty/           Doc-based pretty-printer: build -> lay out to a width -> render
  src/view.rs            display state (highlights, folds, width), held beside the program
  src/dom.rs             builds the program's DOM directly, via web-sys
  src/lib.rs             wasm-bindgen entry points used by the frontend
  tests/                 the test suite (cargo test), one file per pipeline phase
www/                    static frontend (plain JS, ES modules)
  index.html             wiring and a stylesheet — no rendering logic
  pkg/                   generated by `make build` — not checked in
```

The display is built on the Rust side: `render_program` hands the page a finished
DOM element, so `index.html` never parses or formats anything. Highlights and folds
are *display state* keyed by node id, kept beside the program rather than inside it —
which is why a reduction never disturbs which lambdas you've folded, and folding one
never disturbs the program.

See `CLAUDE.md` for more implementation detail (module-by-module breakdown, grammar
precedence gotchas, and how node and binder identity work).
