# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Reduction Stepper is a Rust-to-WASM project: a `stepper-core` Rust crate compiled to WebAssembly and loaded by a static `www/` frontend via ES modules. The project is currently a minimal skeleton (a single `greet` function) — no reduction/stepping logic has been implemented yet.

## Commands

- `make build` — compiles `stepper-core` to WASM via `wasm-pack` and outputs bindings into `www/pkg` (runs `wasm-pack build --target web --out-dir ../www/pkg` from `stepper-core/`).
- `make serve` — serves `www/` over HTTP on port 8585 (override with `make serve PORT=xxxx`) using Python's built-in server. The frontend must be loaded through this (or another) HTTP server, not opened as a `file://` URL, since ES module imports require it.
- `make clean` — removes `stepper-core/target` and `www/pkg` build artifacts.
- Rust tests: `cd stepper-core && cargo test`.
- Typical workflow after changing Rust code: `make build` then `make serve`, and reload the browser page.

## Architecture

- `stepper-core/` — the Rust crate, compiled as both `cdylib` (for wasm-bindgen/WASM output) and `rlib` (for native `cargo test`). Public functions intended for JS must be annotated `#[wasm_bindgen]` in `src/lib.rs`.
- `www/` — static frontend. `index.html` imports the generated `pkg/stepper_core.js`, calls `init()` to load the WASM binary, then calls exported Rust functions directly as JS functions.
- `www/pkg/` — generated by `wasm-pack build`; not source, do not hand-edit. Regenerate with `make build` after changing `stepper-core/src/lib.rs`. This directory is gitignored at the repo root.
- Note: `stepper-core/` contains its own nested `.git` — be aware of this when running git commands from the repo root vs. from inside `stepper-core/`.
